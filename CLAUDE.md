# RPG-s — notes for Claude

Unity 6 (6000.6.4f1) 2D isometric MMORPG, URP 2D, Netcode for GameObjects 2.13, Input System, UI built in code
(`UIFactory`), server authority. A personal test project that takes as much as it can from a **source game**'s client data.
Players test the WebGL build at https://cocomelionas-netizen.github.io/RPG-s/ (Offline mode).

## Working rules (from the owner)

- Answer the owner in **Lithuanian** (chat only). **Everything in the repository is English**: documentation (`Docs/`,
  READMEs), code, names, comments, commit messages.
- **Never write the source game's name anywhere in the repository** (files, folders, identifiers, comments, docs, commit
  messages). Call it "the source game" / "source data". The only exception is the data repository URL below.
- After each change: commit and push straight to `main`. Never force-push. Never touch GitHub Secrets.
- Check the CI build: `https://api.github.com/repos/cocomelionas-netizen/RPG-s/actions/runs?per_page=1`
  (and `/runs/{id}/jobs` on failure); builds take 10–15 min, a newer push cancels an older run.
  Tell the owner the result and what to test in the game.
- No Unity in the cloud: the scene and prefabs are generated by `Assets/_Project/Scripts/Editor/TestSceneBuilder.cs`
  in CI. Never hand-edit `.unity`/`.prefab`. New C# files need no `.meta`; never delete or change existing `.meta`.
- New tests go in `Assets/_Project/Tests/PlayMode`.
- Before pushing, run `bash Tools/CompileCheck/check.sh` (setup once: `bash Tools/CompileCheck/setup.sh`; its
  `CompileCheck.csproj` is committed with `git add -f`, the root `.gitignore` ignores `*.csproj`).
  After builder changes also run `bash Tools/CompileCheck/editor-check.sh` (compiles the editor scripts; CI fails on any
  editor error; its `Editor/EditorCheck.csproj` is committed with `git add -f` too).
- Do not try to get data from the source game's live server (not allowed). Client data is fine.

## Reviews, Unity version, map and performance

- **Reviews**: when asked for a review, audit or list of findings, produce the list only (`/review`, see
  `.claude/skills/review/SKILL.md`) and change nothing until the owner says which findings to fix.
- **Unity 6.6**: CI builds with Unity 6000.6.4f1 and fails on APIs obsolete there (for example `GetInstanceID`), while
  the reference DLLs of the compile checks still accept them. `check.sh` also runs `Tools/CompileCheck/deprecations.sh`
  (a Stop hook in `.claude/settings.json` runs it too); add newly found obsolete APIs to that script.
- **Map fidelity**: the world must match the source game's layout; check changes against the source data (and its
  world map picture) before building on them: `python3 -I Tools/GameData/verify_map.py <source data> out.png`.
- **Performance**: when the world or the number of objects grows, keep only what is near players active (monster
  spawners' activation range), draw props as tiles, give moving HUD layers their own canvases, and rewrite UI texts
  only when their values change. Measure with the in-game F8 overlay (FPS, slowest frame) before and after.

## Source data

Client files come from `https://github.com/DreadmystRPG/steam` (blobless clone is enough): `game.db` (SQLite:
`item_template`, `spell_template`, `npc_template`, `affix_template`, `gameobject_template`, `material_chance_*`,
`player_class_stats`, `npc_vendor`, `dungeon_template`, `loot`, `quest_template`...), `bin/*.exe` (strings, stat
ids/costs), `maps/*.map`. What was taken and how it maps is documented in `Docs/GameData.md`. Generated data lives in
`Scripts/Editor/*Data.cs` (`StartAreaData`, `GearData`, `AffixData`, `DungeonData`) and `TestSceneBuilder.Spells.cs`;
generators are in `Tools/GameData/` (`island.py` → `StartAreaData` (whole island, zones, map labels), `dungeons.py`, `recipes.py`, `world.py` → `WorldMapData`/`VendorData`, `gear.py` →
`GearSourceData`, `townsfolk.py` → `TownsfolkData` (townsfolk, gossip), `monsters.py` → `MonsterData` (monster names, junk), `.map` reader
`map_file.py`).

## What exists (short)

World: the source game's whole island, north up like its map (`island.py`: source (x, y) → cell (597 − y, 688 − x)): its
ground from `fanadin.map` (walls, woods), its zones (13 × 13 blocks, `ZoneMap`), its monsters (source names, junk loot by model)/chests, free waypoints, all its vendors at their spots with their stock (random-quality gear merchants),
Scroll of Returning (back to St. Revere), food, M world map with the source map's labels and level ranges.
Townsfolk: the source's friendly NPCs that are not vendors (guards, priests, council...) at their spots, dressed in Flare
hero layers after their source model like the vendors; clicking one opens the gossip window (the source's gossip menus,
replies, conditions and scripts: `townsfolk.py` → `TownsfolkData`, `GossipCatalog`, `GossipWindow`, `Conversation`).
Testing: F9 cheats window (`Cheats`, `CheatWindow`; only the host's own character, i.e. offline): levels, XP, gold, heal,
god mode, speed, all spells and waypoints, kill around, potions/gems/orbs/gear, empty bag, teleport to any waypoint. No
training dummies in the world (the prefab stays for the tests).
Art: Flare's (CC-BY-SA 3.0, `Assets/_Project/Art/Flare/CREDITS.md`): grassland tiles, lakes, trees, heroes and
monsters in 8 directions, chests, packed by `Tools/Art/flare.py` (`Docs/Art.md`); item and spell icons (Flare, Painterly
Spell Icons, game-icons.net; `Tools/Art/icons.py`). Line of sight: walls block attacks and spells.
Heroes: man or woman (chosen with a new character), drawn in Flare's layers from the worn gear (`HeroAppearance`,
`Tools/Art/avatar.py`): hair or helmet, armor of each kind, weapon and shield change as gear is put on.
Stats: all source stats bought with experience (C: GENERAL / COMBAT / SKILLS tabs with the worn gear on both sides; SPEND EXP → CONFIRM/CANCEL; class-only weapon skills). Equipment: the source's 11 slots (weapon, helm, chest,
feet, necklace, belt, legs, hands, two rings, shield), up to 4 sockets by quality, class gear (bows ranger, staves mage,
plate warrior, robes mage). Items: source gear by level and material, dropped
finished by monsters/chests and sold by the merchants; 7145 affixes; potions/serums; the source's gems (5 kinds, Rough →
plain → Refined); loot window with sparkles.
Chests: crates (gold), locked chests (Lockpicking 2 × level). Spells: Paladin/Ranger/Mage spells to level 20,
Tomes at trainers (Halfrid, Kelda, Gyldan), ranks for experience, ABILITIES window (P; opens beside the character sheet on SPEND EXP), status effects (`StatusEffects`).
Action bar: 12 slots (keys 1-9, 0, -, =) holding Attack, spells and items, arranged by drag and drop.
Transmutation (the source game's crafting): Reginald's TRANSMUTE window (4 × 3 grid + Confirm) makes the source game's
recipes (`Tools/GameData/recipes.py` → `RecipeData.cs`): potion tiers, gems, orbs, keys. No gear crafting.
Dungeons: all 10 source dungeons reachable from this region, laid out from their `.map` files (Wolf's Den, Trog Cave,
Lower Garrison, Decrepit Tower, Abandoned Barracks, Kandorys Undercourse, Desecrated Altar, Salmaster's Descent,
Telamont's Demiplane and Sanctuary) with their monsters, bosses, containers, entry rules and the key chain.
